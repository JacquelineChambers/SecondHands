Observed failure

Can not find firmware data profile.
got nvram data failed.retrying...
DeviceComponentPtr is nullptr

The same missing-profile error occurred with SDK v1.10.37 and v2.10.6. SDK v1 repeatedly retried the NVRAM read; SDK v2 failed while enumerating depth profiles. Returning to SDK v1 after fully closing Windows Camera produced the same result.

Source-code interpretation: Orbbec's depth initialization looks for an internal 1024 × 512 at 5 fps stream to retrieve calibration data. That internal stream is different from the requested 640 × 576 depth output. Its absence prevents this SDK path from initializing. The cause of the missing profile was not established. The requested profile was never negotiated because initialization failed first. Windows Camera was closed during diagnosis. SDK packages were extracted locally and their SHA-256 hashes matched the release metadata.

Compatibility limits affect interpretation. Orbbec lists Windows x86/x64 support; this host runs Windows ARM64 with x64 software emulation. SDK v2.10.6 lists minimum Femto Bolt firmware 1.1.2, above the observed 1.0.9. SDK v1 lists minimum firmware 1.0.6, so the firmware meets its published minimum, but that path also failed. Neither ARM64 incompatibility nor firmware is proven to be the root cause. SDK v2 requirements · SDK v1 requirements

Next checks

  1. Isolate the host compatibility issue.

    Reconnect the camera directly to a USB 3 port on an Intel/AMD Windows x64 computer with adequate power. Use Orbbec Viewer with SDK v1 to test the current firmware and enable depth. A successful stream there would help isolate the issue to this computer's software path.

  2. Match firmware to the SDK before testing v2.

    SDK v2.10.6 requires firmware 1.1.2 or later for Femto Bolt. If adopting v2, follow Orbbec's firmware-update procedure on a supported host, then repeat the capture test.

  3. Validate distance after frames are available.

    Measure a matte target near the image centre at approximately 1 metre and 2 metres. Compare the depth values, check stable readings and movement response, and retain a depth map. If initialization still fails on a supported setup, provide these logs to Orbbec support.

Method and limits

The script attempted a depth-only pipeline using the official SDK, with the intention of checking frame arrival, frame indices, buffer hashes, nonzero depth coverage, and distances scaled into millimetres. Initialization failed before those measurements. Timeouts stopped SDK retry loops. No physical target positioning or tape-measure ground truth was available, and this report makes no accuracy or hardware-pass claim.
